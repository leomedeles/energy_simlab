## Source-quality guidance

| Tier | Source type | Typical use |
|---|---|---|
| A | Standards, official specifications, peer-reviewed papers, established textbooks | Definitions, equations, requirements and validation baselines |
| B | Official open-source documentation/source, vendor technical documentation | Tool behaviour, interoperability and equipment-specific behaviour |
| C | University notes, respected technical articles, conference material | Orientation and supplementary explanation |
| D | Tutorials, forums, informal examples | Discovery only; corroboration required for project claims |

Source quality does not replace relevance. A high-authority reference must still support the exact claim being made.

## Registration rules

1. Assign a stable reference ID after a source is accepted.
2. Record exact edition, standard revision, software version or commit when relevant.
3. Link the source to the claim, model or validation case it supports.
4. Distinguish normative requirements from informative explanation.
5. Do not copy large copyrighted passages; summarize and cite.
6. Record inaccessible, superseded or withdrawn sources rather than silently replacing them.
7. A tool being open source does not establish model validity.
